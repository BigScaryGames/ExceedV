# Rules Reorganization: Real Folder Tree + Embed-Wired Hubs + Editor Tree View

## Diagnosis (agreed)
Mechanics = the embeddable library (stays as-is). Rules = the reading order — currently an implicit, drifting numbering scheme. The tree becomes **physical structure**: chapter folders + chapter pages that embed their children, so "main page = the whole thing" is enforced by actual embeds, and the editor's tree view derives from structure (no manifest to maintain). Dev-only files drop out of the published site via `draft: true` frontmatter (Quartz's `RemoveDrafts` filter already handles exclusion).

## Phase 1 — Vault moves & wiring (all via the editor API, session-logged)
1. **Moves**: 26 hub files → chapter folders via `POST /api/rename` (preview first). Bare-stem links keep resolving; any path-style links get rewritten automatically; git provides the safety net.
2. **Chapter pages + Rulebook root**: create 7 small pages (6 chapters + Rulebook) whose bodies are just ordered `![[embeds]]` — via `POST /api/create` + `PUT /api/record`.
3. **Embed-gap pass**: check each hub actually embeds the mechanics it references (e.g. 4.3 embeds all Condition files); patch gaps via the API. New editor check will flag unwired files.
4. **Dev-only marking** (`draft: true` frontmatter): NPC and Encounter Builder, HEAP of concepts, 0.6 Content Plan Musings, 0.6 Map To Zones Transition, MILESTONES — candidates, confirmed with you in the final summary before relying on it for the site.
5. Editor server: extend `PUT /api/record` with a `draft` toggle (insert/replace/remove frontmatter — parser already reads it).

## Phase 2 — Editor: Rulebook tree view + zoom
1. **`GET /api/rulebook`**: derives the tree — Rulebook page embeds = chapters, chapter embeds = sections, resolved in document order; flags unwired files (in a chapter folder but not embedded) and broken embeds.
2. **Tree view page** (sidebar entry "Rulebook"): expandable hierarchy; each node shows draft badge; click → record view.
3. **Read/zoom mode**: renders a node with embeds expanded inline (tables, headings, bold — read-only lightweight renderer, depth-limited, "expand more" per level) — the "main page is the whole thing" view.
4. **Draft toggle** in the record view header; **new consistency checks**: hub in chapter folder not embedded by its chapter page; chapter page embedding a missing file; draft-marked file embedded in the published tree.
5. Tests: tree derivation, draft toggle round-trip, new checks (temp vault); full suite stays green; real-vault selftest byte-identical.

## Phase 3 — Verification
Moves leave `git status` reviewable per step; pytest + selftest + checker run after each phase; browser pass on tree view, read mode, and a Quartz build smoke test (`npx quartz build`) to prove drafts drop out and nothing broke the site.

## Deliberately out of scope
Dropping the numeric filename prefixes (later pass, mechanical once you like the shape); moving Mechanics into chapter folders (library stays put); any content rewriting beyond embed wiring.
